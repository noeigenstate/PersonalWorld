# 从真实地标到地图资产

## 接线与坐标

从仓库根目录查看这些文件：

| 文件 | 用途 |
|---|---|
| `server/mapScene.mjs`、`mapSceneDetails.mjs` | 建筑轮廓、场馆类别、地点边界和水系 |
| `src/map/styledDistrict.ts` | 完整街区渲染；在对应建筑分支调用专属模型 |
| `src/map/landmarkVenues.ts` | `venueLandmark(id)` 注册、`createLandmarkVenue(rings, kind, height)` 构建 |
| `src/map/venueArchitecture.ts` | 通用场馆与运动场回退 |
| `src/map/amapScene.ts` | 地图相机、叠加层、阴影和实际场景 |
| `tests/venue-models.mjs` | 公开真实轮廓、模型多视角、几何有效性和开销 |
| `tests/scene-region-preview.mjs` | 真实 AMap 中查看街区与特写 |

地图底层负责 WGS-84 → GCJ-02 和局部平面坐标。模型工厂接收转换后的 rings，不在模型里再次转换。x 东、y 北、z 上。大坐标先减建筑中心再计算，最后设置 group 的位置，防止精度损失。优先依据原足迹/相邻场地确定方位，不对照屏幕左右猜东西。

保持足迹尺度，允许屋檐在有参考依据时小幅外挑。平滑轮廓向内拟合，避免覆盖道路或邻馆。圆环/多边形屋面需检查索引绕序和顶面法线；正确阴影不能靠 DoubleSide 随意掩盖反面问题。没有实测高度时明确记录估算值。

## 建模决策记录

每个新增资产在交付文档保留一个简短表：

| 项目 | 要记录的内容 |
|---|---|
| 身份 | 名称、来源 ID、所在地点与模型注册项 |
| 资料 | 来源页面、实际查看的照片/图纸、无法确认的角度 |
| 识别特征 | 最重要的轮廓、开口、结构和立面节奏 |
| 地理不变量 | 足迹、方位、相邻建筑/球场/道路/水面的关系 |
| 美术取舍 | 简化或加厚了什么，哪些高度、颜色和构件为估算 |
| 验证 | 多视角和地图截图、实际开销、尚存差距 |

第一轮只做大体量，检查从地图常用俯角是否能辨认；第二轮添加决定辨认度的结构/立面；最后才处理装饰。对真实馆的结构做简化表达，不逐个复制无法在地图尺度看清的构件。使用相同材质和重复模块，避免随机贴满无关图案。

## 已通过用户视觉认可的实例：拱墅运河体育公园

2026-09-26 的实际成果见 `docs/LANDMARKS_AND_MEMORY_FILM_2026-09-26.md`。照片不同位置共享整个公园的场景；精修只替换两座建筑，湖、河、树、道路、普通街区继续由统一渲染器生成。

### 杭州伞

- 来源：设计方 [Field Hockey Stadium](https://archi-tectonics.com/work/asian-games-2022-field-hockey-stadium) 的鸟瞰、实景、平面、立面和屋盖结构图。
- ID：`osm:way:1084641014`，注册为 `gongshu-umbrella`。
- 识别重点：向东侧真实曲棍球场开放的翼形屋盖；南北端下落；连续环梁、伞骨和斜撑；四处落地支撑；朝场地的阶梯看台。
- 几何：拟合足迹的连续屋顶曲面、加厚边缘、重复支撑和座椅，西侧门厅。缺少来源高度时采用约 36 的场景高度参数，属于艺术估算。
- 配色：奶油屋面、青绿色座椅、小幅金属收边；材质在地图原有灯光下校色。

### 玉琮馆

- 来源：设计方 [Table Tennis Stadium](https://archi-tectonics.com/work/asian-games-2022-table-tennis-stadium) 的实景、平面和结构/形态图。
- ID：`osm:way:1084641019`，注册为 `gongshu-jade`。
- 识别重点：倾斜椭圆顶部、弧形收放的外壳、金色叠鳞与菱形玻璃分区、屋顶环形天窗及底层窗带。
- 几何：真实足迹上拟合的渐变曲面，重复菱形模块合并；缺少高度时约 31 的场景高度参数是艺术估算。
- 曲棍球场同时使用绿色外缘内的矩形蓝色场地、中线和射门弧，以相邻地理关系帮助辨认。

两模型分别约 3.9 万 / 6.1 万三角形；先前检视台含阴影约 21 / 19 次绘制调用，这是该镜头下的参考量级，不是新增模型可无限增加的预算，也不是全公园帧率。材质沿用标准光照，少量漫反射补色匹配既有卡通街区；没有为这两座馆全局重调灯光。

## 可复现验收

```powershell
npm run test:venues
$env:SCENE_LNG='120.09861'
$env:SCENE_LAT='30.31639'
$env:SCENE_CLOSEUPS='gongshu'
node tests/scene-region-preview.mjs
```

观察 `docs/mockups/gongshu-landmark-models-2026-09-26.png`、`gongshu-umbrella-refined-2026-09-26.png`、`gongshu-jade-refined-2026-09-26.png` 和 `gongshu-park-refined-2026-09-26.png`。新增地标应添加自己的预览镜头，不能只复跑拱墅镜头证明别处成功。

失败时按证据定位：形似通用楼→重新检查识别特征；朝向错→检查原足迹与真实邻接关系；亮度不合→先检查材质与法线；地图错位→检查局部坐标与重复坐标转换；湖河/楼体消失→检查遮罩和替换范围。保留上一版可见场景，修好新资产后再替换；不要通过删除完整场景掩盖问题。

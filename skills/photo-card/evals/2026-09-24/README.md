# photo-card 对比测试 · 2026-09-24

## 方法

同一张照片（`photo.jpg`，用户的微信图片，没有 EXIF 和 GPS，窗户贴着"恒彩家装 0571-…"保护膜；个人照片不入库），同样的元数据说明，同样的输出字段，用真实 StepFun `step-3.7-flash` 各跑 5 次：

- **with-skill**：系统提示为当前的 `skills/photo-card/SKILL.md`（去掉 front matter，与服务端运行时一致）
- **without-skill**：系统提示只列出输出字段

元数据里没有写隐私声明，按"未同意"处理，所以期望号码被遮挡。评分全部自动完成，每次生成的卡片保存在 `results.json`。

|---|---|---|---|

| confidenceIsNumber | 置信度是 0–1 的数字 | 5/5 | 2/5 |
| everyClueHasEvidence | 每条线索都有依据和推断 | 5/5 | 5/5 |
| titleNoInferredCity | 标题不写推断出来的城市 | 5/5 | 4/5 |
| asksQuestions | 有 1–2 个确认问题 | 5/5 | 0/5 |
| **合计** | | **44/45** | **23/45** |

唯一一次未通过：号码写成"0571-5670 ****"，只遮了后四位。线上接口还有一道确定性的遮挡（`server/privacy.mjs`），会把它处理成"0571-********"，`tests/api.mjs` 覆盖了这种半遮挡的情况。`asksQuestions` 对基线不完全公平：它的字段说明里没写"最多 2 个"。

## 评分脚本的误判

第一版评分把整张卡片拼成一个 JSON 字符串做正则匹配，JSON 的英文逗号不算中文断句，"保存于 2026 年…"和下一条线索的"拍摄地点"被当成一句话；另一处把"装修公司在杭州（0.9）"当成"照片在杭州"。改为逐字段检查、区分"公司在哪"和"照片在哪"后，用 `--regrade` 对已保存的输出重新评分。

## 复现

```bash
node skills/photo-card/evals/2026-09-24/run-eval.mjs            # 10 次真实调用（RUNS 可调）
node skills/photo-card/evals/2026-09-24/run-eval.mjs --regrade  # 只重新评分
```

# 4D 三维建模：从一张照片到可环视的浮雕

这是**开发** skill，供 agent 修改或验收时空场景的三维部分时阅读。时间片如何分段、每层证据怎么标，是运行时 skill [spacetime-scene](../spacetime-scene/SKILL.md) 的事；这里管"一个时间片的关键照片怎么变成三维"。完整的管线、参数、坐标推导和实验方法见 [浮雕管线与实验](references/relief-pipeline.md)。整体契约见 [4D 实现契约](../../docs/FOUR_D_HOME_RECONSTRUCTION_2026-09-28.md)。

## 能力边界（先说清楚，界面和文档都不许超出）

- 现在做的是**单张照片的 2.5D 浮雕**：网格来自一张图的单目深度。**只有从拍照的位置看才是对的**，偏离几度就会露出被遮挡的部分。它不是扫描出来的场地，不能"漫游"，也不能叫"历史现场"。
- **不能 360° 环绕**：一张照片只拍到物体的一面，背后没有信息。可自由漫游的场景需要**同一时段、同一空间、有重叠视角的走拍视频或多角度照片**。这条链路还没有接到界面（见下面"多视图合成"）；没有这类素材时不启动，不拿单张浮雕冒充，界面上要写明这一点。
- 深度是相对的（单目模型），不含真实尺度。不要用浮雕量长度、面积，也不要把它当建筑测绘。
- 时间片之间不插值：没有拍到的月份不生成"当时的样子"。

## 多视图合成（实验，未接到界面）

`server/spacetimeScene.mjs` 的 `reconstructScene(photos)` 用 Depth Anything 3 的 **multiview** 模式（Base 或 Small 模型，`depth_anything_3_base.safetensors`）把 2–8 张照片一次处理：模型估计每张的相机位姿和彼此一致的深度，每个视图各出一个带贴图的网格，落在同一个世界坐标系里（`sceneWorkflow` 构建工作流）。2026-09-29 的实测：

- **账户里同一事件的 6 张日常照片**（岩壁、老街、乌篷船，互不重叠）：合成出来是一堆碎片，各视图尺度差 10 倍——不重叠的照片不能合成，不要把"同一个事件"当作"同一个空间"。
- **人为制造的 5 张重叠视图**（同一张图平移裁剪）：各视图的范围和尺度一致、平滑衔接，说明流程本身是通的；但没抠掉天空时天空被拉到无限远成一条长白带。
- 多视图下 `DA3GeometryToMesh` 在默认的抠天空 + 置信度过滤下会报"空网格"，要放宽（`skyMask: false, confidence: 0`）；天空需要另外处理。
- 走通到界面还缺：素材准入（视频抽帧或确认重叠的照片）、天空处理、多个视图的清理（`keepFacing` 要用各自视图的相机位置）、自由环绕查看器（全角度旋转、缩放）、覆盖不到的一面必须明说是空的。做完这些再放开"360°"，在此之前不做这个承诺。

## 管线（本机，无第三方）

1. **准入**：`spacetime-scene` 给每个时间片选出 `keyPhoto`（视野开阔、有环境）。人物特写、食物、截图不做。
2. **重建**：`server/spacetimeScene.mjs` 的 `reconstructRelief` 把照片交给本机 ComfyUI：`LoadDA3Model`（`depth_anything_3_mono_large`）→ `DA3Inference`（mono，分辨率 1008）→ `DA3GeometryToMesh`（每隔一个像素取一个顶点，深度跳变上限 0.12，抠掉天空，贴原图）→ `SaveGLB`。一张约 10 秒。默认重建时间片的关键照片；这个时段里的**任何一张照片**都可以在舞台下的胶片带里点选，单独重建（不自动批量重建，避免占满 GPU）。
3. **存储**：GLB 与照片放在同一账户目录 `spacetime/<照片ID>.glb`，旁边的 `.json` 记 `version`；删照片时一并删除。**改了重建方式必须升 `RELIEF_VERSION`**，旧版本的模型会被当作不存在，点击时重建。
4. **查看**：`SpacetimeScene.tsx` 的 `ReliefViewer`，规则见下。

## 网格的坐标约定（查看器全部依赖它）

相机在原点，**看向 −z，y 向上，x 向右**（glTF 约定）；`fx = fy = 0.7 × 图宽`（DA3 单目模式的固定内参），所以画面左右边缘的 `|x/z| = 0.5/0.7 ≈ 0.714`，上下边缘是它除以图片宽高比。UV 原点在左上，`v` 小的顶点在画面上方（y 大）。**不要用顶点的平均方向当光轴**：天空被抠掉、近处被丢弃后，平均方向会歪，背景就对不上。

## 查看器的规则

1. 相机固定在原点（拍照的位置），看向中位深度处，**视场角来自上面的内参**；画布就是照片的画幅（在舞台里留边），视口取照片中央约 95%（`VIEW_SCALE`），给摆动留出余量，摆动时不会露出照片以外的东西；首视图与原照片一致（只是四周各裁掉 2.5%）。
2. 只能绕中位深度做**两三度**的摆动（方位约 ±0.03 rad、俯仰约 ±0.02 rad），**禁用缩放和平移**。绕整个包围盒中心转、拉近相机，会让前景水面这种大面积表面撕成条带、飞出碎片；近处几何的视差最大、单张照片对它知道得最少，摆得越大露出的越多。
3. 加载后先清理网格：**剔掉沿视线方向的拉伸三角形**（法线与视线的夹角接近 90°，`keepFacing`）——人站在地面前时，人与身后地面之间的连接面会被拉成"脚拉长、多出一个身体"的长片；再把**深度向中位数压缩**（`squeezeDepth`，指数 0.5，沿各自的视线移动顶点，首视图不变），近处推远、远处拉近，视差保持很小。
4. 模型后面垫**原照片**，用相同的视角尺度对齐：抠掉的天空、剔掉的三角形露出的是原图；其中被浮雕遮住的内部先补成周围颜色的柔和底色（`inpaint`），撕开时露出柔和的颜色，而不是第二个清晰的人；照片以外是它的虚化。
5. 不做自动旋转和漂浮动画；界面保持静止，只有用户拖动才动。
6. 天空、声音、天气等不是三维的一部分，不在这里生成；它们各自的证据层由 spacetime-scene 标注。

## 常见失败与对策

| 现象 | 原因 | 对策 |
| --- | --- | --- |
| 拖动后水面变成大斜板，碎片飘在空中 | 相机绕远处的包围盒中心大角度转、可拉近 | 相机留在原点，两三度摆动，禁缩放 |
| 人物"割裂"：脚被拉长贴到地面上，旁边多出一个清晰的人 | 人与身后地面的深度突变处有沿视线的拉伸面；垫底照片里的人在撕开处露出来 | 剔掉拉伸三角形（`keepFacing`）、压缩深度、垫底照片里补掉被遮住的部分（`inpaint`）、摆动收小 |
| 首视图下方多出一条模糊带 | 画布比照片高，露出了照片画幅以外的延伸 | 画布留成照片的画幅 |
| 树丛里出现浅色斑块 | 补洞范围扩到了网格上本来没有洞的地方 | 只补被遮住的内部（对遮罩做腐蚀），边缘和小洞保留原照片 |
| 近处的地面、水面缺了一大块 | `discontinuity_threshold` 太小（默认 0.04）把掠射的地面当断层丢了 | 用 0.12；真正的遮挡边缘仍会撕开 |
| 天空处一片空白 | `use_sky_mask` 抠掉了天空 | 垫底原照片 |
| 模型和背景对不上 | 光轴用了平均方向，或视场角靠网格范围猜 | 光轴取 −z，视场角用 0.7 × 宽的内参 |
| 改了重建参数，老照片还是旧效果 | 账户里存着旧模型 | 升 `RELIEF_VERSION` |
| ComfyUI 没运行 | `reliefCapability` 返回原因 | 界面显示原因并只看原图，不要报空白错误 |

## 验收

- `npm run test:skills` 检查代码里的不变量（内参、摆动上限、版本化、禁缩放）。
- `LIVE=1 npm run test:skills` 在本机 ComfyUI 上真实重建一张照片，检查网格：相机朝 −z、边缘 `|x/z|≈0.714`、UV 在 0–1、三角形数在预算内。
- `SPACETIME_PHOTO=<照片> node tests/spacetime-scene.mjs`：走完整个界面链路，并截取初始视角和最大摆动的左右两张。**必须看图**：初始视角应与原照片一致；最大摆动时不能有飘浮碎片、撕成条带的表面，人物要完整、不能出现被拉长的脚和第二个清晰的人。**至少换两张照片各看一次：一张有长水面和近景，一张前景有人物站在地面上**（人物是最容易出问题的情形）。
- 对比记录见 [evals](evals/2026-09-29/README.md)。
- 私人照片只在本机重建，模型不出账户目录；隐私声明（`PrivacyStatement.tsx`）已写明。改存储位置时同步升级 `PRIVACY_VERSION`。

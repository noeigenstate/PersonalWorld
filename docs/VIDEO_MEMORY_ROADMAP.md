# 原始视频理解与混合回忆剪辑：长期计划

记录时间：2026-09-27。用户明确要求作为长期方向保存，**本次黑客松不实现**。

## 要解决的问题

旅行和家庭相册中的真实视频包含照片无法保留的动作、声音、互动和过程。未来应让照片与视频共同参与回忆理解与自动成片，保留原始人物、真实笑声和有意义的小片段。用户仍不需要先写创意或完整脚本。

当前的“自动回忆短片”是已有照片经 StepFun 编排后由 FFmpeg 合成的 MP4。相册可以导入和播放浏览器支持的视频，但当前自动信息卡、故事候选和短片渲染流程没有分析视频内容，也没有自动截取视频片段。不能把导出 MP4 等同于已支持视频理解。

## 拟议流程

| 阶段 | 输入与产物 | 需要验证的问题 |
|---|---|---|
| 本地素材探测 | 编码、方向、帧率、时长、音轨、可靠时间 → 视频清单 | 手机 HDR、可变帧率、HEVC、横竖屏、长视频和损坏文件 |
| 有界代理与分段 | 原片 → 低分辨率代理、镜头边界、候选关键帧和音频片段 | 内存、磁盘、取消恢复、旋转和色彩转换；不上传整本相册 |
| 视频与声音理解 | 带原始时间戳的片段 → 动作、交互、场景、语音文本和不确定项 | 跨帧动作、遮挡、声音与画面对应，不能只用一帧推断全过程 |
| 事实与人物上下文 | 视频证据 + 照片信息卡 + 用户确认 → 可追溯事件和人物关系 | 不自动把所有孩子当成同一个人，不把可见动作夸大成第一次 |
| 叙事与镜头选择 | 候选片段和照片 → 故事、入出点、节奏、字幕、保留原声的位置 | 尽量完整保留动作；不切断一句话、不用相似连拍填满成片 |
| 确定性渲染 | 受约束剪辑清单 → 混合视频、照片、字幕、音乐和真实原声 | 同步、响度、转场、黑帧、画幅与人脸裁切 |
| 成片验收 | 技术检查 + 时间戳抽查 + 用户反馈 | 可播放不等于好故事；分别记录技术成功率和用户愿意保留的比例 |

## 本地模型与编排试验

先建立适配接口和小型授权样本集，再比较本地多模态模型、语音识别和可选云端能力。模型选择、硬件要求、成本与许可在实施时重新核实，不在当前阶段锁定品牌或假定本机显存足够。

每一步保存素材哈希、模型/skill 版本、时间范围、输出与来源引用。对已有分析增量复用；修改一句字幕无需重新解码和理解整段视频。限制代理分辨率、片段长度、并发和总运行时，支持暂停、取消、任务重启与临时文件清理。

模型只输出受约束的叙事和剪辑数据，不输出可直接执行的 shell 命令。渲染器验证素材 ID、入出点、时长与音轨。事实确认继续按账户和实际素材范围生效，不把未知亲属关系或偏好写成事实。

## 分阶段进入条件

1. **单段视频**：本地探测、关键帧、原声和一条完整动作的截取，能够追溯原片时间戳。
2. **单次出游**：混合少量视频与照片，自动生成一条温暖回忆，优先保留有意义的真实声音。
3. **多次到访 / 时间篇章**：有确认身份和可靠日期后，再关联跨月素材。

至少覆盖竖屏、横屏、HDR、长片、无声、嘈杂、多人、未知日期和低配机器；记录处理耗时、峰值资源、失败恢复、字幕事实偏差及人工修改比例。技术指标与家庭观感分别评价。

现阶段继续完善照片信息卡、人物确认、故事编排和地图。该文档是长期计划，没有新增视频理解的运行入口或后台任务。

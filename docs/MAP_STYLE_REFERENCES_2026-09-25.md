## 共通规律与当前差距

1. **有限造型比无限变化更有风格。** 当前楼体使用六套随机色板，虽然避免白膜，却使街区缺少共同身份。下一轮按街块使用 2–3 个基础色，只有照片附近和地标用少量强调色；统一窗格宽高比、檐口厚度、屋顶内缩规则。
2. **丰满来自轮廓和接触关系。** 概念图的树冠宽、树干短、绿地像厚毡，楼体有厚檐与基座；当前树仍像稀疏的小球，楼体多是直立长方柱。让树丛成簇，楼体顶部和底部有稳定的圆润过渡，比给表面增加随机小物更有效。
3. **水面是一整块视觉材料。** 当前均匀的短水纹在截图里像网格。概念图以蓝绿明暗大块变化、少量宽的白色高光和清楚的奶油色河岸表达釉面感。先做静态／慢速着色与岸线，再考虑昂贵的实时反射。
4. **光照是全局规则。** 当前地面、楼体、树木和水面分别有颜色，但都偏平。统一暖色主光、冷色环境补光、同方向软阴影和少量高光；照片标记须始终比背景醒目。
5. **不同缩放级别给不同密度。** 全国／城市概览保留人生据点与故事线；街区近景显示窗户、树冠和水面细节。摄影作品和个人事件是产品中心，地图负责提供可信、可探索的舞台。

## 下一轮先做的样本验收

- 在同一上海视角，对比目标图与真实截图，检查江面是否有宽的亮区、岸线是否连续、远近树木是否呈簇、楼群是否能一眼看成同一套建筑语言。
- 近景至少保留东方明珠的辨认轮廓，以及照片标记、场景说明和事件线的可读性。
- 继续保持真实建筑轮廓和道路锚点；缺失高度、窗户、树木与水面高光是艺术生成并清楚标注。
- 将建筑与树木重复件批量合并或实例化。桌面回归之外，要在真实手机设备测帧率；电脑的窄视窗截图不能替代设备测量。[Three.js InstancedMesh 文档](https://threejs.org/docs/pages/InstancedMesh.html)。

## 本轮应用到上海样本

[桌面实测](mockups/map-scene-after-reference-study-2026-09-25.png)与[手机窄视窗实测](mockups/map-scene-after-reference-study-mobile-2026-09-25.png)来自真实高德浏览器测试。

- 楼体改为约 155 米街块共享主色；仍有少量粉、紫建筑作点缀。统一加厚基座与挑出屋檐，未测得高度的楼层略收敛。
- 树冠放大，增加两个灌木团块；近地标的小景屋顶、树木和东方明珠球体一并加厚。
- 河面以蓝绿大块明暗和少量宽高光替代密集水纹，增加连续浅色岸线。草地使用低对比明暗纹理。
- 调整暖色主光与环境补光。这一版仍偏平面插画感，尚未达到概念图中的柔和环境遮蔽、玻璃釉面和复杂屋顶材质；这些应继续在同一地标样本精修。
- `npm run build` 与 `npm run test:amap` 通过；测试包含上海预览、普通 GPS 照片、地标照片、缩放返回、场景开关和拖动。真实手机 GPU 帧率未测。

# Personal World · 参赛演示与交付计划

更新时间：2026-09-28。用户已确认：demo **5 分钟以内，视频格式不限**；征文仅记录参赛过程，无格式与篇幅限制。以下为可直接录制的脚本，**当前是脚本，不是已完成的比赛 demo 视频**。

## 作品主张

把散落的家庭照片，变成能持续修正和积累理解的个人记忆：知道谁在其中、发生在哪里、哪些片刻可以连成故事，并自动做成一段值得留下的短片。

地图是记忆的空间入口；人物、事实与故事构成共同底座；短片让这些理解成为能直接观看的结果。

## 4 分 10 秒演示脚本

| 时段 | 屏幕动作 | 旁白草稿 |
| --- | --- | --- |
| 0:00–0:25 | 中国总览 → 有照片的城市 → 一张真实家庭照片。显示作品名。 | 手机记录了很多日常：去公园、看雪、做手工，还有路边的一支甜筒。照片越来越多，我们却很少有时间把它们重新串起来。Personal World 想保存的，是这些照片之间的生活。 |
| 0:25–1:05 | 打开已导入相册和自动理解状态；打开一张信息卡，依次指向拍摄信息、可见观察、推断依据。 | 导入后，系统读取已有的时间和地点，调用 StepFun 理解照片。拍摄信息、画面观察和推断各自保留来源。缺少的信息不会直接当成事实；用户已经确认的内容，会成为后续理解的依据。这里展示的是实际处理结果，耗时过程经过剪辑。 |
| 1:05–1:40 | 从杭州总览进入拱墅运河体育公园，平移看湖河、场馆和多组照片；再切一处海岸。 | 同一个公园的多个拍摄点会共享完整场地。我们保留真实地理结构，把树木、水面、建筑和一些重要地标变成卡通场景。地图让人想回到记忆发生的地方。特殊场馆来自专属模型和验收，当前并不保证任意地点自动达到这种精修程度。 |
| 1:40–2:30 | 人物与故事 → 已确认人物及关系 → 保存一次真实资料纠正 → 队列状态 → 相应故事新版本。 | 理解一张照片还不够。系统需要知道，多次出游里出现的是同一个人。人物确认和关系绑定到稳定 ID。名字或关系变化后，相关经历重新排队理解，再回看跨地点的线索。知道某人是姥姥，不代表每张老人照片都是她；逐图匹配和家庭关系是两份不同证据。 |
| 2:30–3:35 | 展示两个自动发现的不同主题；点开照片依据；播放两种真实短片各约 20 秒，保留原速和音乐。 | 故事可以围绕一个地点，也可以围绕陪伴、手上的动作，或不同月份出现的甜筒。系统先提出角度，再用原始证据复核，交给短片导演。用户不需要写创意。画面、停留、字幕和音乐跟随内容组织，最后由本机导出真正的 MP4。资料变化后，保留中的相关影片可以重新生成新版本。 |
| 3:35–4:10 | 简图：观察 → 人物关系 → 持续理解 → 创作；回到地图和一张温暖照片。 | 我们把观察、人物确认、持续理解和创作拆成可复用的流程与 skills，让所有表达共享同一份记忆。现在仍有侧脸漏检、地理资料不足和长期作品更新等边界。下一步会继续提高这些环节的质量，也会加入原始视频理解。希望留下的不是一堆自动生成的描述，而是一段段能够继续被理解、被修正、被重看的生活。 |

配音建议自然语速，画面变化时留停顿；最终控制在 4:00–4:30，硬上限 5:00。可调整旁白，不需要机械念完所有字。

## 录制所需的真实画面

1. 已登录主页、城市卡通标签、照片组可点击。
2. 一张清晰的信息卡；拍摄事实、观察、推断同屏可读。
3. 拱墅运河体育公园的场地全景和专属场馆近景；另一处地理风格不同的区域。
4. 已确认的人物关系，以及相关故事依据。录制真实变更与其后果，等待过程可快进并标注。
5. 两段叙事角度、版式不同的私人相册实际 MP4。测试插画不能混作真实成片。
6. 一张四步架构示意，结尾保留作品名与可交付入口。

合并最新远端后，人生管家从地图地点打开；顶栏不再使用原来的导航标签。另有账户硬盘备份和重复照片整理，可在导入段各用一句带过，保持核心演示在 5 分钟内。备份需要先完成新版隐私说明确认，再录制正式流程。

避免在录制时临时批量导入整个相册；事先完成分析和地图数据加载，仍保留真实进度/更新镜头。录制时隐藏账户邮箱、环境配置和管理工具，不展示 API Key。素材保持本地，比赛上传另走实际提交步骤。

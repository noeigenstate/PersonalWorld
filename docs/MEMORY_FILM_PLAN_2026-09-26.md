## 核心选择

用户当前的测试素材以女儿为主。最有辨识度的演示是：**在同一座公园，看到不同时间的女儿，再把这些真实片段整理成一段成长回忆。** 地图提供地点与重访关系，时间线展示变化，视频承载情感。照片本身、家长的叙述和可核对的日期应当是成片的主体。

地图值得继续完善到“地点可辨认、重要水系和场馆存在、交互稳定”。继续投入精确复刻每一座特殊屋顶，成本会明显上升。参赛阶段建议把有限的精修模型用于确实会展示的建筑，并把模型作为可复用资产接入通用场景；同时优先打通真实照片 → 故事 → 可导出的短片。这是产品取舍建议，并非已经核实过比赛评分权重。

## 当前已经具备与尚缺部分

| 已有能力 | 当前边界 |
|---|---|
| 照片导入、EXIF 时间/GPS、文件哈希去重、本地原件 | 文件修改时间不能当拍摄时间；已有 4×4 色彩签名用于找参考图，不是成熟的连拍去重 |
| `photo-card` 单图信息卡、`photo-context` 多图佐证 | 还没有面向剪辑的清晰度、主角位置、镜头价值和安全裁切信息 |
| `event-analysis` 事件重建、用户确认 | 还没有跨多次事件的成长章节与影片叙事 |

| StepFun 对话、语音转文字、语音合成 | 可复用旁白能力；现有录音功能是问管家，不是影片音轨系统 |

## 三类值得做的短片

| 类型 | 组织方法 | 第一版建议 |
|---|---|---|
| 一次温暖的出游 | 到达／探索／互动／一个精彩瞬间／收尾 | 40–60 秒，10–16 张；先做这一类，证据和时间关系最清楚 |
| 同一地点的几次重访 | 同一个地点，按到访日期分章；寻找相似视角或同类活动做呼应 | 60–90 秒；“这座公园，陪你长大”很适合当前素材 |
| 一段成长 | 按月或阶段取样；日常、家人互动和关键活动保持平衡 | 60–120 秒；有生日或家长确认后才写具体年龄、成长里程碑 |

关键时期的精彩瞬间可作为成长片中的章节：生日、开学、一次演出、学会某项技能等。需要照片证据或家长确认。素材只有普通日常时，也可以拍成好看的片子；不必强行编一个“重大转折”。

## 先把三种对象分开

- **地点 Venue**：同一个公园、商场。可以包含不同拍摄位置，供地图共用场景。
- **到访 Visit**：某一天或一段连续时间的一次经历。同一个公园三个月去过四次，应保留四次到访。
- **故事 Story**：根据目的从一次或多次到访中挑选材料。例如“一次出游”和“女儿半年的成长”会选择不同的材料和顺序。

此次地图合并只共享地理场景，不会合并照片原时间、事件或用户原件。未来影片也不应直接拿地图上最近的照片按序播放。

## 建议的 skill 编排

不要把所有照片连同“剪个温暖视频”一次交给模型。用有结构输出、可缓存、可单步重做的流程：

| 阶段 | 输入与输出 | 执行者 |
|---|---|---|
| 素材整理 | 原件哈希、时间来源、清晰度/曝光、近重复组、宽高 → 素材清单 | 程序；保留用户强制入选的照片 |
| 事实整理 | 复用信息卡、元数据和家长补充 → 有来源 ID 的事实与不确定项 | 复用现有 skills，增量处理缺失项 |
| `memory-story`（拟议） | 主角、时间范围、地点/主题、事实 → 到访、章节、可讲述的变化 | 模型负责选择叙事，不能补造人生事实 |
| `memory-shot-select`（拟议） | 候选图与章节 → 代表镜头、替代图、主体框、选择理由 | 程序质量筛选 + 模型语义选择 |
| `memory-film-director`（拟议） | 故事与候选镜头 → 确定的剪辑清单、字幕、旁白、节奏 | 模型输出受约束 JSON |
| 成片 | 校验过的清单 → 预览、MP4、字幕、素材出处 | 确定性渲染器，首版建议 FFmpeg |
| 成片检查 | 输出文件与清单 → 时长、音轨、黑帧、裁切/字幕检查结果 | 程序检查 + 关键帧视觉复核 |

“主角是我的女儿”应成为用户确认的故事上下文。用户选中的照片可以作为主角样本，但不能把所有出现的小朋友都自动认作同一人。生日、称呼、家长想保留的片段允许一次补充并复用；没有年龄信息也能用实际日期讲述成长。

## 让成片温暖的具体做法

1. **用变化和呼应组织内容。** 同地点的旧照与新照、同类活动前后的变化，比每张图平均播放三秒更有意义。找不到可靠呼应时使用普通时间章节。
2. **连拍选代表帧，保留情绪。** 同一动作挑一至两张；清晰度只是因素之一，稍有运动模糊但有纪念意义的照片可由用户保留。
3. **镜头有主次。** 环境图交代地点，互动图推进经历，精彩瞬间多停留一会儿，再用安静的照片收尾。照片停留约 2.5–5 秒，以叙事和音乐节奏调整。
4. **运动克制。** 照片轻推近、轻横移、少量叠化；先保护脸部和动作主体，再决定构图。横图进入竖屏时可以保留全图并补柔和背景。
5. **字幕短而具体。** 日期、地点、一句有依据的描述就够了。“人生第一次独立走路”要有家长确认；程序最多能说“这批照片里最早的一次”。
6. **声音可选。** 一段轻柔音乐可以撑起整片。旁白只讲关键几句；家长自己的录音也很有纪念价值。素材中有真实笑声、说话声时，后续视频版优先考虑保留。
7. **地图少量使用。** 开头或章节间用 2–4 秒展示同一地点和日期变化；画面主体留给照片。地图不需要在每个镜头反复出现。

## 编辑清单的职责

模型输出 `storyPlan` 和 `editPlan`，不生成 shell 命令。每个镜头至少包含：

```json
{
  "assetId": "已存在的素材 ID",
  "chapterId": "某次到访",
  "durationSeconds": 4,
  "layout": "contain-soft-background",
  "motion": "gentle-zoom",
  "caption": "已核对的短字幕",
  "evidenceIds": ["照片或用户补充的事实 ID"],
  "selectionReason": "这一张在该章节中的作用"
}
```

这是建议结构，尚无运行时 schema。实际接入时应校验素材存在、日期次序、时长上限、重复率、主体裁切和字幕事实。人物关系或年龄未确认的字段留空，不因文案需要而补全。

缓存以素材哈希、skill 版本和输入上下文为键。用户改一句话、换一张照片或换配乐，应只重做受影响的阶段。每一步保留输入版本、输出和简短理由，方便比赛中解释 Agent 做了什么。

## 渲染路线

建议首版使用本机 Node 服务调用 FFmpeg，输出 1080p、30 fps 的 MP4；先做一套稳定模板，再加竖屏和更多风格。FFmpeg 官方提供照片推拉的 `zoompan`、转场的 `xfade`、音频淡入淡出的 `afade/acrossfade` 和响度处理的 `loudnorm`；渲染前统一分辨率、帧率与时间基准。[FFmpeg 滤镜文档](https://ffmpeg.org/ffmpeg-filters.html)

当前原件在浏览器 IndexedDB。导出时由浏览器只把选中的素材交给本机渲染任务，使用独立临时目录，完成/取消后清理；不能让服务端假设自己可以直接读取浏览器里的照片。模型看过的信息卡、缩略图与最终高清渲染原件也应分开处理。

首版需要新增任务 API、进度/取消、结果下载和临时文件生命周期；并确认运行机器可用的 FFmpeg 编码器、字体和随包配乐。先生成低分辨率预览，用户能替换素材、改字幕和去掉旁白，再导出高清。原有 StepFun 配置可以用于叙事和旁白，不需要为首版引入额外大模型厂商。

## 参赛顺序与验收

1. 选一组真实亲子出游素材，做“事实 → 故事清单 → 可编辑预览 → MP4”的闭环。
2. 加入同一公园的两次或更多重访，让地图日期、照片和影片章节对应。
3. 有足够跨度与身份确认后，再做按月成长片。

验收至少覆盖：一次出游、同地多次重访、跨月成长、连拍很多、时间/地点缺失五类素材。检查：

- 每个镜头能回到原照片，每条事实字幕有证据；同地不同日期没有误合并。
- 原件未被改动，导出没有黑帧、拉伸、截脸、字幕越界和明显音量突变。
- 失败可重试，取消可结束，改字幕不重复分析所有照片。
- 家长是否觉得选中了值得记住的瞬间，是否愿意保存成片；这部分需要真人反馈，不能以接口成功率代替。

初始规划时尚未进行流水线实测；目前照片合成短片已有实际导出与浏览器验证，详见交付记录。原始视频理解和混剪仍未实现，也没有该能力的成功率数据。应分别记录“任务成功导出率”和“无需大幅修改即可保留的成片比例”，不以少量成功样本推断长期质量。

# 边看边讲：实施与验收

日期：2026-09-29。比赛材料硬截止为 **9 月 29 日 24:00，北京时间**。用户要求一次完成已讨论的讲述改造，然后由用户验收。当前范围是可直接播放的回忆讲述；比赛 demo 本身的录制和上传另行核对。

## 为什么改

旧路径让模型给每张照片写一句话，再逐张朗读；换照片基本等于换解说。单图信息卡承担了本不该由它独自承担的故事编排。新路径先找照片之间的具体联系，再围绕这个联系安排叙述和画面。

## 入口和行为

- 话筒旁 **听故事 → 自动挑选，讲一段新故事**。不用提供创意。
- 同一菜单列出最近生成的讲述，点标题可以重听。
- 语音和文字依旧共用 `/api/butler`。文字可说“用甜筒讲一段回忆”“讲讲毛蛋和爸爸的回忆”。
- 播放器支持单图、旁白跨图、并排对照、无声看图和结尾回看。音频真实进度决定跨图切换；暂停、续播和选段会同步管理声音。
- 相邻照片在约 1.8 km 内不反复移动地图；跨地区时才移到新地点。
- 播完可自愿补充一件记得的事，绑定对应照片，进入原有人物与故事资料库。可以立即按新补充重讲。
- TTS 失败时显示原因并按阅读节奏保留字幕和照片，不会瞬间跳完。

## 数据与运行时 skill

根目录 [`skills/memory-storytelling/SKILL.md`](../skills/memory-storytelling/SKILL.md) 是服务端实际读取的运行时 skill。

```text
原始时间地点 + 照片观察 + 服务端确认的人物/关系 + 用户补充
                    ↓
          选题与选片（参考已有故事和最近主题）
                    ↓
          独立重看所选照片（不读取旧卡和故事草稿）
                    ↓
          围绕具体发现写作并安排照片
                    ↓
          独立编辑读取原始证据和所选实图，返回最小文字补丁
                    ↓
          校验照片编号、人物在场、强事实断言、长度与结构
                    ↓
          保存私人讲述 → TTS → StoryStage
                    ↓
          用户可选补充 → 原有持续理解队列与短片依赖
```

写作阶段不把精确日期/地址当作逐张报幕材料；它们仍用于选题、事实核对和画面标注。选题模型的解释也不作为作者的新事实。复核不能改选片、不能填满原稿留白。事实信息来自原始资料，生成旁白不回流成为事实。

实测发现旧信息卡曾将低头照片描述为熟睡、把 T 恤图案当成孩子佩戴的帽子。因此在写作前增加独立观察：读取当前账户最多 8 张所选照片的预览图，暂不提供旧卡与草稿，避免旧文字影响再次观察。新观察供写作使用，编辑阶段再结合图片核对。没有可用预览图时保留文字路径，并记录实际复核的图数；不能把这种情况称为经过实图核验。此次不会把这些临时观察自动覆盖原始信息卡，防止派生叙述变成新事实。

有实际照片时正常使用四次模型调用：选题、独立看图、写作、复核；纯文字资料为三次。各阶段最多修复一次格式或校验问题。照片分组数量、引用和旁白长度先由写作阶段修正，再交给文字编辑，不要求编辑修改它无权修改的布局。没有无限重试或失败后编造通用故事的兜底。当前新编排可能需要数分钟，已有且资料未变化的讲述直接复用。

本机为讲述写作单独配置 `STEPFUN_STORY_MODEL=step-5-preview`，仍走 Step Plan。选题、独立看图、事实核对及照片分析保持主模型 `STEPFUN_MODEL=step-3.7-flash`。未配置独立写作模型时全部沿用主模型。试验中让预览模型承担所有阶段，曾出现空 JSON、格式漂移和超时，因此按职责分工，并采用 medium 推理强度；这并不保证模型每次都能完成合格讲述。

## 持续更新与存储

- 人物 ID 和关系从服务端图谱取，浏览器旧的“家长 / 小孩”文字不能覆盖已确认身份。
- 来源签名包括观察、人物成员、关系、用户补充、相关图谱内容、skill 版本和模型。来源有变动，重听会重编，不直接播过时文案。
- 模型生成期间来源发生变化，拒绝发布旧稿；用户删图会清理引用该图的已存讲述。
- 每账户保留最近 12 段，目录为 `server/data/storytelling/<账户哈希>/stories.json`；菜单最多显示 4 段。与其他账户隔离。
- 记忆补充允许直接绑定照片，无需捏造一个人物 ID；原有事件重理解、图谱和短片 enrichment 都可使用它。
- 根据项目 `CLAUDE.md` 的存储变更要求，隐私声明升级为 `2026-09-29.1`，包含讲述存储和复核图像发送。用户刷新后可能需要阅读并同意新版声明。

“持续更新”目前指资料修改会进入原有理解队列，下一次重听会核对来源；不会在播放中途偷偷替换正在讲的一段，也不保证打开菜单前就已后台生成所有新讲述。

## 可复现命令

```powershell
npm run build
npm run test:api
npm run test:skills
node --experimental-strip-types --test tests/storytelling-playback.mjs tests/event-understanding-sync.mjs tests/identity-graph.mjs
npm run test:smoke
```

实际私人相册可通过同一服务逻辑准备讲述，问题文件是 JSON 字符串数组：

```powershell
node scripts/prepare-storytelling.mjs --account=<本机账户ID> --questions=<私人问题文件.json> --out=data/exports/storytelling-review
node scripts/preview-storytelling.mjs --account=<同一账户ID> --manifest=data/exports/storytelling-review/manifest.json
```

准备脚本会保存到该账户自己的讲述库。预览脚本只读照片，在隔离浏览器中挂载真实 `StoryStage`，拦截所有应用 API，使用实际 TTS 检查图片、声音及桌面/手机布局；不登录真实账户，不修改相册。生成轨迹、私人照片、声音和截图留在忽略目录，不能加入 Git。

独立试验可给准备脚本加 `--store=data/exports/<试验目录>/private-cache`，避免未经验收的试验故事进入用户菜单。

公开合成材料的单例配对测试：`node skills/memory-storytelling/evals/run.mjs`。该测试保存用过的 skill 和原始响应，以便核对；不能用一个样例宣称总体成功率。

## 能力边界

自动发现切口、编排、复核、播放与资料失效链路已经独立实现。创意和事实准确性仍受单图观察、人物匹配和生成模型影响；独立模型复核不等于人类审校，规则检查也只能覆盖部分强断言。文案应通过真实相册验收，不能以接口成功代替“故事有趣”。目前仍是照片与语音组成的观看体验，未加入原始视频理解。

## 未经编辑的自动试验

`data/exports/storytelling-auto-check-v9/` 留有独立运行，未放进用户菜单。四阶段共约 120 秒，选择并复核 5 张真实照片，输出 6 段。它正确去掉了旧卡中把衣服图案当帽子的说法，也完成了并排、留白与回看。但文案仍在罗列服装和画面，对闭眼、张嘴写出了“不太配合、发呆”，编辑未能识别全部问题。

据此给意愿/心情断言增加了程序检查与复核要求，未经用户补充支持时不能通过。这个修正有回归用例，但没有据此宣称自动生成已达到验收稿的文案水平，也没有把 1 次完成视为成功率。当前适合先验收两段已明确标注开发校对的讲述；新故事的表现另行评价。

已校对验收稿保留原始生成版本及开发校对记录；升级到当前播放器和来源签名时只做兼容核对，没有把它们标记为当前四阶段重新自动生成。

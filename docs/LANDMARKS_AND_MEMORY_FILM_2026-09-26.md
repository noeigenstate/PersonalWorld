# 场馆精修与自动回忆短片

2026-09-26。在 `9a30630` 的完整地点场景上继续，范围为拱墅运河体育公园的两座特殊建筑，以及无需创意输入的自动回忆短片。

## 1. 特殊建筑

| 地标 | 原有表现 | 新模型 |

| 玉琮馆，OSM way 1084641019 | 通用浅圆顶 | 随原轮廓拟合的斜切椭圆体、弧面金色叠鳞、局部菱形玻璃、屋顶收边、环形天窗和底层窗带 |

`src/map/landmarkVenues.ts` 以 OSM 建筑 ID 注册专属资产，`styledDistrict.ts` 识别后替代该建筑的通用模型。以后新增有特点的建筑，应增加有公开依据的注册项；未注册建筑继续使用已有完整通用表现。完整公园、湖河、周边街区和照片共享逻辑沿用上一轮。

保留真实建筑位置和地面轮廓，粗糙屋面轮廓向内平滑；缺少测量时使用艺术估算高度。构件合并为少量绘制批次，屋面法线和阴影在实际地图近景检查。两座模型约 3.9 万和 6.1 万三角形，检视场景含阴影绘制约 21 / 19 次调用；这不是整个街区的性能测量。

依据来自设计方的[曲棍球场项目页](https://archi-tectonics.com/work/asian-games-2022-field-hockey-stadium)和[综合体育馆项目页](https://archi-tectonics.com/work/asian-games-2022-table-tennis-stadium)，包含平面、立面、屋盖结构与实景。下载的参考照片位于忽略目录 `server/data/venue-references/`，仅作本机观察，没有作为可分发纹理。地理资料继续遵循 OSM / OpenMapTiles 署名。

### 精修能力已经固化

开发 skill：[landmark-refinement](../.claude/skills/landmark-refinement/SKILL.md)，由原有 `map-scene-styling` 路由到它。详细[流程与已验收实例](../.claude/skills/landmark-refinement/references/workflow.md)记录了输入资料、构件取舍、坐标、模型注册和多视角验证。当前模型外观在本次 skill 整理中保持不变。

依赖过程为：**真实建筑身份与足迹 → 多角度参考和图纸 → 最有辨识度的形态特征 → Three.js 程序化几何 → 统一材质与光照 → 模型和真实地图验收 → 资产注册复用**。资产制作由开发 agent 按 skill 执行，运行时按建筑 ID 自动装配。无需把私人照片上传到新的 3D 生成商，也没有依赖临时的图片贴片。关键瓶颈是新建筑参考资料的完整性、识别特征提取和建模验收；skill 固化成功路径，不能保证无参考资料的任意地标一次成功。

## 2. 自动短片链路

```mermaid
flowchart LR
    A[真实相册与已有信息卡] --> B[去重与时间采样]
    B --> C[memory-film skill / StepFun]
    C --> D[有来源的剪辑 JSON]
    D --> E[校验 ID 时序 时长 字幕]
    E --> F[选中照片传到本机服务]
    F --> G[FFmpeg 渲染]
    G --> H[播放 下载 MP4]
```

### 默认行为

1. 至少 6 张已有信息卡和预览的照片；跳过视频、截图、很小的图片和完全重复的内容哈希。分析空闲 10 秒后自动开始，不要求指定标题、人物、创意或脚本。
2. 最多向模型发送 80 条均匀覆盖时间的候选，复用信息卡可见内容和用户确认事件。模型此阶段不接收全量照片、GPS 或原片路径。
3. `skills/memory-film/SKILL.md` 自动判断一次出游、同地重访或时间相册，选 6–12 张并给出短字幕与依据。程序过滤虚构 ID、重复选片、过长时长和明显未经确认的年龄/第一次表达，按可靠时间排列。
4. 模型不可用时明确显示降级为按日期编排，不伪称已经完成语义理解。前端可查看选片依据、暂停与重新编排。
5. 当前账户浏览器从 IndexedDB 读取选中原片，处理 HEIC 与朝向，缩至最长边 1800 px，以 JPEG 逐张送到本机服务。原片不可用时使用已有预览。照片不经过其他图像/视频生成商。
6. FFmpeg 输出 720×960、24 fps、H.264/AAC MP4：保留完整照片，1.2% 缓慢推进、0.5 秒叠化、中文字幕、日期和结语。音乐是程序合成的轻柔分解和弦，没有下载商业歌曲或克隆声音。

这是保留原始人物形象的照片短片。当前成长能力是时间片段编排，未确认的人物不能自动跨照片关联，也不能自动断言年龄或第一次。信息卡错误可能影响选题与字幕；程序约束不能彻底证明全部自然语言文案的真实性，用户可追溯来源并补充事实。

### 人物与故事补充

运行时 skill [memory-film](../skills/memory-film/SKILL.md) 在每次 StepFun 编排时真正加载。它根据可靠日期、可见动作和已确认关系选择一条主线，组织环境、互动、细节和结尾；缺少某类素材就略过，不编造完整剧情。已确认关系可参与自然叙述，例如“我和女儿”；不据此推断用户是爸爸或妈妈。未确认人物仍使用可见动作，不能把年龄差写成祖孙，也不能把吃东西写成最爱。

可选入口在短片中的“人物与故事补充”。保存适用于本片照片的事实后，自动生成开启时会只用这条片子的照片重新编排一次；暂停时等手动编排或重新开启。清除、修改均可，原成片继续保留在历史中。选片和文案始终能自动完成，不要求用户写创意。

数据按**账户 + 照片 ID**保存在媒体目录的 `context/` 中，作为每条候选的 `story` 送给模型。24 小时任务清理不会清除这些确认。补充不写入共享 skill、不传播到未确认照片；同一账户再次用到相同照片时会复用。编排缓存包含这些事实，变化后旧结果不会被当成新编排。`fromJob` 重编排仅接受当前账户的原片任务；补充 API 同样检查账户、来源标记和任务状态。

程序校验同时修复了“从其他照片借用已确认亲属关系”的问题：镜头字幕只检查本照片的确认，标题和结语只检查实际入选素材。规则仍不是完整的自然语言事实证明器。

### 文件与编排

| 文件 | 职责 |
|---|---|
| `src/components/MemoryFilms.tsx` | 自动触发、进度、准备照片、暂停、播放、下载、选片依据 |
| `src/lib/memoryFilm.ts` | 候选与批次哈希、从当前账户取图、图像规格化 |
| `server/memoryFilmPlan.mjs` | 加载 skill、调用 StepFun、校验与降级 |
| `server/memoryFilmContext.mjs` | 按账户和照片保存可修改、可清除的事实补充；摘要和修订指纹 |
| `server/memoryFilms.mjs` | 账户隔离任务、上传、单渲染队列、取消、缓存、Range 响应 |
| `server/memoryFilmRender.mjs` | 固定约束的 FFmpeg 调用、字幕、合成配乐 |

相同批次只自动生成一次，手动可以重新编排。服务端保留同账户最近 3 条任务，24 小时过期清理。完成后清理上传图片、片段、字幕临时文件、字体副本和音乐源；保留短片、封面、剪辑依据。浏览器原件不删除。暂停取消当前任务；渲染器升级可恢复旧渲染失败一次，复用原方案，避免再次调用模型和无限重试。

默认目录 `server/data/memory-films/` 被 Git 忽略。指定 `USERS_FILE` 时媒体目录跟随该账户库目录，避免测试进程碰到本机真实任务；`MEMORY_FILMS_DIR` 可覆盖目录。不要提交私人视频、原片、任务 JSON 或私人封面。

本机已安装 FFmpeg/FFprobe。其他环境需要 FFmpeg（libx264、AAC、drawtext、xfade）和中文字体，可指定 `FFMPEG_PATH`、`FFPROBE_PATH`（测试）、`MEMORY_FILM_FONT`。浏览器需保持打开到选片和上传完成，之后本机服务继续渲染。服务重启中断渲染时可重新生成。
